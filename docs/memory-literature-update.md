# Memory optimization literature update

Search completed 28 October 2026 UTC. Scope: the [actual algorithms and allocations](memory-algorithm-inventory.md) in this fork, including the surrounding load/verify/free paths. This is a targeted primary-source review, not an exhaustive systematic review of all literature. “New” below means newly reviewed for this project, not necessarily newly invented. A primary abstract or implementation read is explicitly distinguished from examination of the paper text.

## Decisions

Experimentally implemented exact immutable logical-metadata sharing: parser-owned objects become matcher-owned shared objects; the scan still reads ordinary pointers and evaluates the original expression. The existing hash-table implementation supplies collision handling and full equality. This shifts work/ownership to loading, while adding a small loader module and a uniqueness-dependent memory cost; it is not a claim of fewer lines or invariants overall.

**Acceptance result:** retain the implementation as an experimental patch, not in the active scanner. A repeated duplicate-pattern fixture changes all-match order because existing sort ties use allocation addresses. Ordinary corpus equality and strong-threat selection are insufficient to pass the stricter order gate. See [the implementation report](logical-sharing-implementation.md).

The best next investigations under the complexity constraint are (1) prove field dependencies and remove redundant stored values, (2) count exact ordered candidate suffix sharing before changing traversal, and (3) account for region lifetimes and allocation rounding before trying a new allocator. They have plausible paths to replacing existing machinery. Broad learned codecs, moving-object runtimes, decoder caches and custom compression hardware do not qualify for integration in this pass.

## Theory-to-practice tests

1. **Eliminate information before encoding it.** If a field is a total function of retained fields for every accepted signature, storing it is redundant. Establish the invariant in parser and verifier code, exercise integer bounds and malformed input, then remove the field and its ownership/access code. A correlation observed only in the current database is insufficient. This is the strongest prospective complexity reduction.
2. **Share ordered tails, not sets.** Count equal candidate suffixes including multiplicity, order, `next_same` and all record attributes. A shared immutable suffix can reduce allocation without a decompressor. Estimate savings after directories and indices. Reject if maintaining the original order requires per-scan sorting or a merge heap.
3. **Use the index-size denominator.** A 50% reduction of a 1 MiB directory saves 0.5 MiB, not half the dataset. Rank/select and MPH improvements should be charged only to the index they replace, with full keys and payload retained. Large-bitvector results need small-array crossover tests.
4. **Separate logical size from resident size.** Sharing can reduce allocated payload while a pool retains pages. Measure compiled RSS, construction high-water, post-scan memory, old/new reload overlap and cgroup usage. Compare lifetime-separated regions only after attributing the unexplained allocation budget.
5. **Stress dependent accesses.** Candidate floods, repetitive byte streams, random misses, high-output inputs and cold pages reveal costs hidden by sequential codec benchmarks. Include full ordered output comparisons, not just equal match counts.
6. **Treat arbitrary valid custom databases as the worst case.** An exact interner can save nothing and add its keys/index. Random-like digest keys and unique metadata cannot be promised compression. A conservative worst-case bound is part of the design, not an optional benchmark.

## Immediate leads revisited

- L23 implemented, then gated out: shared descriptor/expression ownership saves memory and needs no scan-time table lookup, but changes allocation-dependent ordering.
- L24 adjacent-run sharing: simpler than global interning, but less sharing; prior run counts depended on the flawed export and are withdrawn until recomputed.
- L25 allocator gap: census attribution remains necessary; no “all fragmentation” estimate.
- L26 byte-only token specialization: substantial potential, but another verifier representation/path; not integrated under the current gate.
- L27 range-count defect: corrected; prior logical template estimates and derived totals are superseded.
- L28 rank/select: strongest for large monotone directories, weak for tiny exception masks.
- L29 OBASE: borrow static lifetime/role grouping, reject runtime movement here.
- L30 output forests: worth an exact ordered-tail census, not a wholesale automaton replacement.
- L31 interner overhead: explicit all-distinct regression bound and duplicate-dependent break-even; no universal saving claim.
- L32 ordering gate: repeated strict-order failure, preserve the default representation.
- L33 post-link compaction: investigate reusing an existing relocation phase only; pool residency and ownership remain unresolved.

No paper establishes that this fork can reach 202.042 MiB while preserving its current end-to-end performance. The measurements in the implementation report are the evidence for this pass; literature results are leads and constraints, not substitute measurements.
