# Memory structures and algorithms: implementation inventory

28 October 2026 UTC. Read with [implementation and measurements](logical-sharing-implementation.md) and [literature review](memory-literature-update.md).

This inventory covers the large measured engine allocations and the algorithms that build, reference, verify, release or replicate them. It also identifies adjacent allocations not yet independently measured. It is not a claim that every allocation in every ClamAV parser has been traced. Sizes are decimal bytes divided by 1,048,576 (MiB), from the pinned database of 3,628,192 signatures, not a universal workload average. “Integrated” means present in the retained scanner; the flat hash store still requires its pre-existing build option. Logical sharing is an isolated experimental patch rejected by the strict ordered-output gate; the retained scanner keeps its original logical layout. Standalone codec measurements are not scanner RSS.

## Largest resident structures

| Allocation / measured size | Representation and algorithms actually in use | Operations and invariants | Source anchors / optimization boundary |
|---|---|---|---|
| Pattern records + pointer directory: 149.587 MiB | 1,508,210 `cli_ac_patt` objects; 96-byte records and 8-byte directory entries. Pointers to tokens, prefix, extension and name; logical IDs, offsets, lengths, type and multipart metadata. | Random candidate verification; full pattern semantics and exact offset arithmetic. | `libclamav/matcher-ac.h`; `matcher-ac.c::cli_ac_scanbuff`, parser insertion. Struct packing alone has little remaining padding. Functional dependencies, direct indices and field ownership are the larger opportunities. |
| Pattern/prefix token arrays: 86.177 MiB | 16-bit tokens; byte values plus tags for wildcards, nibble matching, case options, special tests. Sequential and backward prefix checks; bounded alternative matching. | Byte-only specialization must retain tagged patterns and boundary semantics. | `matcher-ac.c`, `matcher-ac.h`, `readdb.c`. Existing byte/dictionary/grammar/block experiments are standalone; adding a second verifier path is not a complexity-neutral change. |
| Name text, all counted families: 83.560 MiB; unique text 83.133 MiB | NUL-terminated names; raw stable strings. Flat hash store uses one raw arena per family with 3-, 4- or native-width offsets. AC/logical names still individually owned. | Direct reporting, ordered callbacks, caller-visible stable pointers until engine destruction; NULL differs from empty. | `matcher-hash.c::cli_hm_compile`, `readdb.c`, public scanner API. Whole-name interning has only ~0.427 MiB text opportunity here. Substring compression needs decode ownership/lifetime management. |
| AC transition rows: 75.164 MiB | 256-entry rows of 32-bit node IDs; full byte-alphabet dispatch, shared rows where already supported. Failure links resolved during construction; flat node access. | One byte transition in hot loop; adversarial repetitive input matters. | `matcher-ac.c::ac_node`, `ac_scan_node`, trie construction and compilation. Cyclic factoring/grammar tables are unintegrated; their memory savings previously cost substantial worst-input time. |
| Candidate links + pointer directory: 69.578 MiB | 2,279,919 `cli_ac_list` entries, 24-byte three-pointer record plus 8-byte directory. `me`, builder-node/runtime-next union, `next_same`. | Sort comparator, merge/link operations, ordered duplicate chains and traversal; these are an ordered multiset, not an unordered set. | `matcher-ac.c::insert_list`, `patt_cmp_fn`, `sort_list_fn`, `link_node_lists`, `link_lists`. Reordering for compression can change selected threat. Plain 32-bit IDs are a simpler candidate than variable-length compression, but require a sound construction/lifetime design. |
| Exact digest bytes: 49.038 MiB | MD5/SHA1/SHA256 fixed-width exact keys, partitioned by file size and purpose. | Hash input, locate size bucket, exact binary search of sorted digest range; original equal-key selection retained. | `matcher-hash.c/h`. Random-looking digests are not an attractive lossless-compression target. Fingerprints, MPH and retrieval functions alone cannot replace exact membership. |
| Hash metadata, names excluded: flat layout totals 68.687 MiB including digests | Existing open-addressed size hash, triangular probe sequence and bounded capacity; values are bucket indices. Compact ranges, contiguous digest arrays, name-offset arrays. Wildcard buckets separate. | Lookup equality/probe semantics unchanged. Loading and sorted compilation preserve duplicates. | `matcher-hash.c/h`, `hashtab.c`. Already integrated opt-in; builder pool is disposable. Compiling both layouts simultaneously increases peak. |
| Logical rule headers + directory: 52.420 MiB retained, 14.296 MiB in rejected prototype | 312,310 ordered records. Inline TDB replaced by pointer to immutable shared TDB; expression strings shared exactly. IDs, flags, type, bytecode index and names stay per rule. | Same recursive expression evaluation and same rule order. No runtime interner access. | `matcher.h::cli_ac_lsig`, experimental `lsig-store.c`, `readdb.c::load_oneldb`, `load_oneyara`, `matcher.c::lsig_eval`. Experimental patch only; see measured unique storage and all-distinct bound in implementation report. |
| Logical TDB auxiliary arrays / expression strings | Retained: per-rule scalar/range/string/macro arrays and expression text, with field pointers into the arrays. Prototype: exact hash-consing with full coordinate-and-byte keys. | Mutable parser object transfers once to matcher ownership. NULL, range endpoints, macro presence and pointer offsets remain distinct. | Experimental `lsig-store.c`, existing `hashtab.c`. Hash collisions always compare complete keys. The interner stores keys and tables through engine lifetime, so low duplication can increase memory. |
| AC nodes: 12.725 MiB | Flat node array, IDs, transition-row references, failure/output references and flags. | BFS construction, queue traversal, scan-time ID lookup. | `matcher-ac.c/h`. Flat arena replaces pointer-rich node allocation; index width must support largest valid databases. |
| AC extensions: 0.801 MiB counted headers | Sparse extension pointers: special alternatives, custom data, boundaries, relative offsets. | Rare verifier branches; recursive/alternative matching as supported by original engine. | `matcher-ac.h::cli_ac_patt_ext`, `matcher-ac.c`. Header census does not include every pointed-to allocation. |
| Static q-gram prefilters: 0.500 MiB | Each filter has two 65,536-byte tables `B` and `end`, plus length state. Bit-parallel static-pattern filtering over two-byte grams. | Conservative candidate rejection before exact matching; must never produce a false negative. | `filtering.c/h`. This is not an exact membership dictionary or a generic Bloom-filter allocation. Small total makes replacement low priority. |

## Surrounding structures and lifetimes

| Area | Data structures / algorithms | Memory and correctness considerations | Source |
|---|---|---|---|
| Logical state per active scan | Prefix-sum row directory; compact count, first-offset and last-offset arrays; fixed-width exception rows for bytecode/macros/Yara. | Integrated compact state. Worker count and nested scans multiply writable storage. Lazy epochs/sparse state add mutation and wraparound invariants; no such new mechanism in this pass. | `matcher-ac.c::ac_build_lsig_layout`, `cli_ac_initdata`, accessors in `matcher-ac.h` |
| Subsignature match histories | Dynamic per-rule/per-subsig lists and offset vectors, multipart rings/history and Yara match records. | Attacker-controlled repetitions can dominate scan scratch even with a small resident engine; preserve match/scan limits and error reporting. | `matcher-ac.c::lsig_sub_matched`, `lsig_increment_subsig_match`, `cli_ac_chkmacro` |
| Relative offset scratch | Indexed minimum/maximum offsets, executable section metadata and logical rule offsets. | Some fields are derived only for a subset of offset types. A conditional correlation is not a global invariant. | `matcher.c`, `matcher-ac.c`, `matcher-bm.c` |
| Boyer–Moore family | Shift tables, suffix buckets, linked pattern objects, pattern directory and sorted relative-offset positions. | Pattern-count and target dependent; not separately charged by the AC census. Retain short-pattern and wildcard behavior. | `matcher-bm.c/h` |

| Byte comparison rules | Per-rule byte extraction/comparison metadata, offsets and operators. | Exact signedness, endianness, widths and boundary/error handling matter more than codec size. | `matcher-byte-comp.c/h` |
| Bytecode | Instruction/operand arrays, constants, function metadata, VM/JIT context and execution scratch. | Untrusted-input execution limits and verification retained. Not measured separately in this census. | `bytecode.c`, `bytecode_vm.c`, `bytecode_api.c`, `bytecode_detect.c`, related headers |
| Yara | Parsed strings, hash tables during loading, arena-held instructions and runtime match lists. | Parser/build arenas and rule ownership interact with test matcher destruction. Shared empty descriptor is immutable. | `readdb.c::load_oneyara`, `yara_*`, `yara_exec.c` |
| Fuzzy and phishing matchers | Rust fuzzy-hash maps; regex lists and specialized URL/domain checks. | Account for foreign allocations and capacities; do not confuse approximate similarity matching with exact signature membership. | `libclamav_rust`, `phishcheck.c`, `regex_list.c` |
| Evidence / verdict aggregation | Ordered evidence vectors and severity categories, callback emission, first-hit stop rules. | Any deduplication must preserve stronger evidence, order and selected name. Representation changes cannot silently weaken verdicts. | `libclamav_rust/src/evidence.rs`, `matcher-ac.c`, `scanners.c` |
| Clean scan cache | SHA256/length keys, partitioned splay trees, linked replacement state and locks. | Disabled equally in reported benchmarks. Capacity is a time/memory knob only with unchanged cache validity/invalidation semantics. | `cache.c` |
| Engine allocator | Linked `mmap` regions, bump allocation, size-class fragment free lists, alignment and tail release. | Freed fragments do not automatically reduce RSS. Pool high-water minus counted payload is not proof of fragmentation. | `mpool.c`, especially map creation, allocation/free, `mpool_flush`, destruction |
| Input mappings | Memory mappings / buffered reads, page locks/references and age-based eviction; digest caching. | File-backed pages still count toward physical/cgroup memory. Demand loading changes fault latency, not the information content required by an adversarial scan. | `fmap.c/h` |
| File parsers / decompression | Archive indexes, decompression windows and buffers, recursion stack, executable sections, document/XML/JSON structures. | Workload-dependent transient peaks may exceed resident-database savings. Preserve all existing limits; do not lower limits to claim equivalent-functionality savings. | `scanners.c`, archive/document/executable parser modules |
| Trust and allowlisting | Certificate chains, ASN.1 objects, trust hash sets, false-positive exact hash matchers. | Trust outcomes and malformed-input failures must remain unchanged. Counts partly overlap hash families; avoid double-counting. | `cert_util.c`, `crtmgr.c`, `matcher-hash.c`, `readdb.c` |
| Reload and concurrency | Engine generations, reference counts, live scan contexts, old/new database overlap. | Two engines may coexist. Sharing immutable pages across processes/generations requires a separate lifecycle and trust design. Not implemented here. | `clamd`, engine reference/free APIs |
| Construction temporaries | Parser buffers, growable arrays, qsort work, trie/BFS queue, hash construction pool, interning keys. | Optimize lifetime before adding compressed storage. Experimental logical interner adds temporary key encoding and retains unique keys. Peak must be measured separately. | `readdb.c`, `matcher-ac.c`, `matcher-hash.c`, `lsig-store.c` |

## Existing research prototypes, not production representations

The repository also contains column-wise constant/affine/frame-of-reference/exception codecs; bitmap rank and popcount selectors; monotone/Elias–Fano indexing probes; grammar/OnPair token stores; block decompression; FSST-family name coding; transition factoring; and zero-default state experiments. Their files are under `tools/compact-memory/` and their evidence under earlier `docs/*results/` directories. They do not all coexist in the scanner and their individual minima cannot be added as a validated engine budget.

In particular, a 12.012 MiB pattern-layout or 8.223 MiB candidate-layout result is a standalone representation measurement. Reconstructing a whole record on a real candidate miss, maintaining output order, allocator overlap and decoder tables all affect the end-to-end outcome. The previous logical template numbers also need the range-count correction described in the new implementation report.

## Search design derived from the inventory

Search families used: exact immutable hash-consing; lifetime/region allocation; double-array AC and shared output forests; correlated column compression and functional dependencies; random-access short-string/grammar compression; constant-time rank/select; monotone offsets and succinct dictionaries; exact static membership and retrieval; run-length dictionary matching; regex automaton lower bounds; object/page locality and memory tiering; hardware random-access compression. Searches covered 2025–2026 and previously unread older primary papers, with a final freshness check for September–October 2026.

For every candidate ask: which bytes disappear, which new bytes appear, what is the worst dependent-access count, who owns decoded memory, what input defeats locality, and what changes to ordering/trust/error behavior? These questions distinguish a representation substitution from a new runtime subsystem.
